# Contributing to dingoFW

Read the [shared contributing guide](https://github.com/corygrant/dingoElec/blob/main/dev/CONTRIBUTING.md) first. It covers the branch flow, PRs and changes that span repos. **Open PRs against `development`.**

## Build

You need `arm-none-eabi-gcc` (CI uses 14.2.Rel1) and `make`.

```bash
git clone --recursive https://github.com/corygrant/dingoFW.git   # ChibiOS is a submodule
# or, on an existing clone:
git submodule update --init --recursive

make BOARD=dingopdm_v7      # or dingopdmmax_v1, canboard_v2
```

The output goes to `build/<board>.hex|.bin|.elf`. Run `make clean` before you switch boards. Board definitions are in `boards/`, and OpenOCD target files are in `target/`.

Before you open a PR, build **every board** your change could affect. CI builds all.

## DBC files

The DBC files in `dbc/` are generated by `dbc/dbc_builder/main.py`. If you change a CAN message, update the builder rather than editing the `.dbc` files by hand.

## Testing

In your PR, list the board you flashed and what you checked. If you only built the code without flashing it, say so.
